# ХӨРС — Хүнсний ногооны хүргэлтийн сайт

Жинхэнэ ажиллагаатай хувилбар: Node.js/Express backend + SQLite өгөгдлийн сан
(захиалга бодитоор хадгалагдана, серверийг унтраагаад асаахад ч алдагдахгүй) +
QPay-тэй холбогдох боломжтой төлбөрийн урсгал.

## Бүтэц

```
hors-app/
├── server/
│   ├── index.js     # Express сервер, бүх API endpoint
│   ├── db.js        # SQLite холболт, схем, анхны бүтээгдэхүүний өгөгдөл
│   └── qpay.js       QPay Merchant V2 интеграц
├── public/
│   └── index.html   # Фронтэнд — API-тай холбогдоно
├── data/             (автоматаар үүснэ) SQLite файл энд хадгалагдана
├── .env.example      Тохиргооны жишээ файл
└── package.json
```

## Локал дээр ажиллуулах

```bash
npm install
cp .env.example .env
npm start
```

Дараа нь `http://localhost:3000` хаягаар нээнэ. Захиалга өгөх, хянах бүгд
ажиллана — QPay тохируулаагүй бол зөвхөн төлбөрийн QR гарахгүй, бусад бүх
функц (сагс, захиалга, хянах явц) хэвийн ажиллана.

## Бүтээгдэхүүн удирдах (`/admin.html`)

`таны-домэйн/admin.html` хаягаар орж, `COURIER_PIN` кодоороо нэвтэрнэ (хүргэгчийн
хуудастай ижил PIN). Энд:

- **Дууссан гэж тэмдэглэх** — ✓/✕ товч дарж бараагаа түр унтраавал сайт дээр
  харагдахгүй болно (устгагдахгүй, зөвхөн нуугдана). Дахин ирэхэд дахин ✓ дарна.
- **Үнэ шинэчлэх** — тоог засаад талбайгаас гарахад автоматаар хадгална.
- **Шинэ бүтээгдэхүүн нэмэх** — нэр, ангилал, нэгж, үнэ, эможи бөглөөд нэмнэ.
- **🗑 Бүрмөсөн устгах** — буцаах боломжгүй тул болгоомжтой ашиглана.

## Хүргэгчийн хуудас (`/courier.html`)

Хүргэгч тань `таны-домэйн/courier.html` хаягаар орж, PIN кодоо (`.env`
дэх `COURIER_PIN`) оруулаад идэвхтэй (хараахан хүргэгдээгүй) бүх захиалгыг
харна. Захиалга бүрд:

- Харилцагчийн нэр, хаяг, захиалсан ногоо, нийт дүн, төлбөрийн төлөв харагдана
- 📞 товч дарж шууд утасдана
- Нэг товчоор дараагийн шат руу шилжүүлнэ: *Хүлээн авав → Түүж байна →
  Хайрцаглаж байна → Хүргэлтэнд гарлаа → Хүргэгдсэн*
- Хүргэгдсэн гэж тэмдэглэмэгц захиалга жагсаалтаас арилна
- Хуудас 10 секунд тутам автоматаар шинэчлэгдэнэ

PIN-ээ `sessionStorage`-д хадгалдаг тул хөтчийн tab хаагдтал дахин нэвтрэх
шаардлагагүй. Нэг PIN-ийг бүх хүргэгчид хуваалцаж болно, эсвэл хүргэгч
тус бүрт өөр өөр код хэрэгтэй бол мэдэгдээрэй — нэмж хийж өгье.

## API endpoint-ууд

| Method | Path | Тайлбар | PIN шаардах уу |
|---|---|---|---|
| GET | `/api/products` | Бүтээгдэхүүний жагсаалт (зөвхөн идэвхтэй) | Үгүй |
| GET | `/api/admin/products` | Бүх бүтээгдэхүүн (дууссан зүйлийг оруулаад) | **Тийм** |
| POST | `/api/admin/products` | Шинэ бүтээгдэхүүн нэмэх | **Тийм** |
| PATCH | `/api/admin/products/:id` | Бүтээгдэхүүн засах (үнэ, active гэх мэт) | **Тийм** |
| DELETE | `/api/admin/products/:id` | Бүтээгдэхүүн бүрмөсөн устгах | **Тийм** |
| POST | `/api/orders` | Захиалга үүсгэх (`{customerName, phone, address, note, items:[{productId, qty}]}`) | Үгүй |
| GET | `/api/orders/:orderNumber/track` | Захиалгын явц, түүх, дэлгэрэнгүй | Үгүй |
| GET | `/api/courier/orders` | Хараахан хүргэгдээгүй бүх захиалга, дэлгэрэнгүйтэй | **Тийм** (`x-courier-pin` header) |
| POST | `/api/orders/:orderNumber/advance` | Захиалгыг дараагийн шатанд шилжүүлэх | **Тийм** |
| GET | `/api/admin/orders` | Бүх захиалгын жагсаалт (товч) | **Тийм** |
| POST | `/api/qpay/callback` | QPay-ээс төлбөр төлөгдөх үед дуудагдана | Үгүй (QPay дуудна) |

PIN-тэй endpoint-үүдийг дуудахдаа `x-courier-pin: <PIN>` header (эсвэл
`?pin=<PIN>` query) илгээнэ. `.env` дотор `COURIER_PIN` тохируулаагүй бол
эдгээр endpoint 503 буцаана.

## QPay-тэй холбох (жинхэнэ төлбөр авах)

1. https://qpay.mn дээр **Бизнесийн бүртгэл** хийж мерчант эрх авна (энэ
   алхмыг зөвхөн та — бизнесийн эзэн — хийж чадна, би үүнийг таны өмнөөс
   хийж чадахгүй).
2. Зөвшөөрөгдсөний дараа QPay танд дараах зүйлийг илгээнэ: `username`,
   `password`, `invoice_code`.
3. `.env` файл дотор эдгээрийг бөглөнө:
   ```
   QPAY_BASE_URL=https://merchant-sandbox.qpay.mn/v2   # тест горим
   QPAY_USERNAME=...
   QPAY_PASSWORD=...
   QPAY_INVOICE_CODE=...
   QPAY_CALLBACK_URL=https://таны-домэйн.mn/api/qpay/callback
   ```
4. Сервер асаах бүрд `QPay тохиргоо: холбогдсон` гэж хэвлэгдэж байвал бэлэн.
5. Тест (sandbox) орчинд бүрэн шалгасны дараа `QPAY_BASE_URL`-ийг
   `https://merchant.qpay.mn/v2` болгож бодит горимд шилжинэ.

QPay callback URL нь **олон нийтэд нээлттэй** байх ёстой тул localhost дээр
ажиллаж байхад QPay рүү мэдэгдэл ирэхгүй (доорх deploy хэсгийг үзнэ үү).

## Серверт байршуулах (deploy)

Хамгийн хялбар сонголтууд:

- **Railway** эсвэл **Render** — GitHub repo холбоод, environment variable-үүдээ
  (`.env`-тэй ижил утгууд) тохируулаад deploy хийхэд бэлэн. SQLite файл
  хадгалагдах persistent disk эсвэл volume нэмэхээ бүү мартаарай (эдгээр
  платформын free tier-т заримдаа файл систем түр зуурынх байдаг).
- **VPS (жишээ нь DigitalOcean, орон нутгийн hosting)** — `node`, `pm2`
  суулгаад `pm2 start server/index.js --name hors` гэж тогтмол ажиллуулна.
  Nginx-ээр reverse proxy хийж, Let's Encrypt-ээр HTTPS сертификат авна
  (QPay callback HTTPS шаардана).
- Домэйнээ (жишээ нь hors.mn) DNS-ээр серверийнхээ IP рүү чиглүүлээд,
  `QPAY_CALLBACK_URL`-ээ шинэ домэйнтэйгээ тааруулна.

## Дараагийн бэхжүүлэлтүүд (жинхэнэ бизнест шилжихээс өмнө зөвлөж байна)

- Одоогийн PIN хамгаалалт хялбар (бүх хүргэгч ижил кодтой). Хэрэглэгч олон
  болвол хүргэгч тус бүрт өөрийн нэвтрэх эрх (username/password эсвэл токен)
  болгож бэхжүүлэх нь зүйтэй.
- Захиалгын дугаарыг санамсаргүй биш, өгөгдлийн сангийн auto-increment дээр
  суурилсан илүү өвөрмөц ("collision" гарахгүй) байдлаар үүсгэх.
- SMS/имэйл мэдэгдэл нэмж, захиалга бүрийн явц өөрчлөгдөх бүрт хэрэглэгчид
  мэдэгдэх.
- SQLite-аас Postgres руу шилжих (олон concurrent хэрэглэгчтэй болвол).
